# VoiceMemoReminder 界面与交互精修设计

> 日期：2026-05-30
> 状态：已评审，待实现
> 目标设备：reTerminal E1003（16 灰阶，触摸）。E1001 / E1002 的文本降级界面不在本次改动范围。

## 背景与目标

在 PlatformIO 迁移与首版界面改版之后，主界面、开机页与录音交互仍有缺陷：无时间提醒被填入猜测的钟点、卡片日期与时间重叠、底部提示过浅、开机刷两页、录音另开全屏页。本次迭代重做 Header、修复列表卡片细节、合并开机页、将录音处理态内联，并新增电池/WiFi 状态显示。屏幕文字统一英文。

## 1. 无时间提醒（逻辑修复）

提醒按时间信息分三种情况，分别决定「大时间」格的显示：

| 情况 | due_label | 大时间格显示 |
| --- | --- | --- |
| 用户说了精确钟点 | `""`（空） | `HH:MM`（24 小时制） |
| 用户只说了时段 | 时段词（见下） | 时段词 |
| 用户完全没提时间 | `NONE`（哨兵值） | 留空（不绘制） |

- 时段词使用全称：`morning→Morning`、`afternoon→Afternoon`、`noon→Noon`、`evening/night→Evening`。
- `due`（绝对时间）在三种情况下都仍由模型给出，仅用于排序；「没提时间」时其钟点不在屏幕上暴露。
- `MemoUI` 渲染逻辑：`fuzzyLabel == "NONE"` → 大时间格不绘制；`fuzzyLabel` 为其它非空值 → 显示该词；`fuzzyLabel == ""` → 显示 `HH:MM`。
- `MemoClient` 提示词新增规则：完全没提时间时输出 `due_label="NONE"`；并将时段词从缩写（AM/PM/Eve）改为全称。

## 2. Header 重做（仅 `drawTodoList` 的 16 灰阶分支）

三栏布局，每栏上下两行，左右对称：

```
┌────────────────────────────────────────────────────┐
│ [▣]                 13:56                   85% ▰    │  左:logo  中:大时间  右:电池(上)
│ Notes            Apr 28  Tue                ((•)) ✓  │  左:Notes 中:日期星期 右:WiFi(下)
│                                                      │  (无分隔横线，留白过渡)
│ ╭────────────────────────────────────────────────╮ │
│ │ ...卡片列表...                                   │ │
```

- **左上**：剪贴板/清单图标（方框 + 顶部夹子 + 内部横线）在上，`Notes` 文字在下，上下堆叠。
- **中间**：大时间（24 小时制，最大字号）在上，日期 + 星期（`Apr 28 Tue`）在下，水平居中。
- **右上**：电池（图标 + 百分比）在上，WiFi（已连/未连图标）在下，上下堆叠。
- **取消**：原 `Reminders` 大标题、原右上角 `UPDATED`/`READY` 状态 badge、Header 与列表之间的分隔横线。
- 时钟未就绪时大时间显示 `--:--`。

## 3. 列表卡片（保持圆角卡片，仅修复）

卡片整体风格不变（圆角矩形、左侧复选框、完成/逾期的底色区分均沿用现状）。修复三点：

- **日期格与大时间拉开间距**：当前两者垂直距离过近导致重叠；增大间距使其分离。
- **右侧标签全称**：日期格用 `Today` / `Tomorrow` / `Day after` / 星期全称（`Wednesday`）/ `Jun 15`（≥7 天）；不使用 `This wk`、`Tmrw` 等缩写。
- **无时间留空**：见 §1。

## 4. Footer（加深）

底部提示行（`Hold KEY0 to add. Tap a box to check off.`）保留，颜色由 `kUiMuted`（浅灰）改为 `kUiText`（深），确保可读；右下角计数（`count/kMax`）保留。

## 5. 开机页（合并为一页）

开机不再绘制两个独立的全屏 `drawStatus` 页面。改为一页，复用主界面 Header 风格（logo + `Notes` + `--:--`），中间一行状态文字随启动阶段更新：`Starting…` → `Connecting WiFi…`。错误（麦克风失败等）在同一页中间区域显示一句说明。

## 6. 录音处理态（内联，不开新页）

- **录音开始**：维持现状——不刷屏（ePaper 全屏刷新 ~1.5s，会让 I2S DMA 丢失开头语音）。反馈仅靠蜂鸣器 + LED。
- **录音松手后的处理阶段**（转写 + 总结，约 5–10 秒）：取消全屏 `drawProcessing` 页。改为在主界面 Header 右上区域显示静态等待标记（圈形图标 + `Processing…`），列表保持可见；处理完成后 Header 恢复电池/WiFi 显示并刷新列表。
- ePaper 无法做真正的旋转动画，等待标记为静态图形。

## 7. 电池读取（新功能）

参数来自 Seeed Arduino 外设 cookbook：

- 使能脚 `BATTERY_ENABLE_PIN = GPIO40`（E1003 专属；E1001/2/4 为 21）。
- ADC 脚 `BATTERY_ADC_PIN = GPIO1`。
- 读法：`pinMode(EN, OUTPUT)` → 拉高 → `delay(5)` → `analogReadMilliVolts(ADC)` → 拉低；`analogReadResolution(12)`、`analogSetPinAttenuation(ADC, ADC_11db)`。
- 电压 = `mv / 1000.0 * 2`（分压比 ×2）。
- 百分比：`(V - 3.3) / (4.2 - 3.3) * 100`，钳制到 0–100（线性估算，满电 4.2V、低电 3.3V）。
- **待真机验证**：Seeed wiki 自身提示 GPIO40 与原理图存在不一致，烧录后需确认该脚正确。GPIO40 / GPIO1 当前未被项目占用。

## 8. WiFi 状态

`WiFi.status() == WL_CONNECTED` → 已连图标；否则未连图标。

## 技术约束

- 录音开始时禁止刷屏（见 §6）。
- ePaper 等待标记为静态，无动画。
- 屏幕文字全英文（不引入中文字库）。

## 测试

## 边缘情况 / 风险

- 电池使能脚 GPIO40 与原理图的一致性（真机确认）。
- 时段词全称（`Afternoon`）在大时间格的宽度——必要时实现阶段缩小字号。
- `NONE` 哨兵值必须在 UI 层转为「不绘制」，不可意外显示。
- 处理态在 Header 右上绘制时与电池/WiFi 图标的区域复用——处理时临时替换，完成后恢复。
- LLM 偶发不遵循「无时间→NONE」：回退为显示 `HH:MM`（与精确时间同路径），不破坏布局。
